# Reuse map

Snapshot classifications, not new authority. `B` = current baseline within its
stated boundary; `P` = provisional/flow-local evidence; `R` = retained product or
technical primitive; `U` = no defined V1 contract. None implies production
adoption. Exact current status stays in the [primary](../../../src/views/internal/design-system/component-catalog-primary.ts)
and [support](../../../src/views/internal/design-system/component-catalog-support.ts)
catalogs; bare entries inherit `undefined` authority from the catalog helper.

## Transfers explicitly rejected

- `TransactionWalletAction` tracks a token in a wallet; despite its name it is
  not a connect/switch/confirm-wallet action.
- `TransactionOutcomeStatus` and the transaction progress stepper are flow-local
  checkpoint evidence, not replacements for canonical Lifecycle Status or an
  auction count. No celebratory result when only launch submission completed.
- `transactionTaskGeometry.substantialWidth`, outcome minimum height, attached
  brand surfaces and gray fact dividers do not transfer to a full-width working
  section. Use matching relationships, not the entire shell recipe.
- The existing table `useProjectionFocus` helper repairs a hidden focused
  counterpart via `data-table-focus`; it does not preserve edits, prevent double
  timers or provide a generic state owner. A single responsive task tree is the
  starting preference; alternative renderers need explicit lifecycle proof.
- Current history provenance format and its vertically centered numeric cells
  stay unchanged. The new workspace must not reopen completed history refinements.

## Component-work disposition

No shared component implementation is required before Claude's audit returns.
Gaps DS11, DS14, DS19–21 should first be solved as narrowly scoped auction
compositions using accepted primitives and retained mechanics. Extract a shared
relationship only when the actual implementation demonstrates repeatable need.
