## Main conclusions

- Actions, fields, identity, inline feedback, help, independent disclosures and
  structural surfaces have usable existing owners. No new universal Card, Row,
  transaction controller or page shell is justified.
- The accepted `Metric` API does **not** provide a compact 14px inline variant.
  Its value sets its own 16px role. Compact pairs already have a 14px/20px
  label/value recipe in transaction details and Governance-style evidence;
  consume the matching roles on both sides instead of shrinking only the parent.
- Lifecycle semantics are available; their current 28px geometry remains an
  explicitly provisional dependency. Auction number, rebalance progress,
  permissionless deadline and transaction confirmation are different facts.
- Generic determinate progress, chart anatomy and sliders remain undefined in
  the catalog. Existing product implementations are evidence to preserve and
  adapt, not accepted V1 components. Address these locally when real states are
  known; do not stop to design a complete chart system first.
- Transaction checkpoints provide useful action stability, input retention and
  scoped recovery relationships. They do not supply an auction state machine or
  justify importing Zapper/Vote Lock amounts, shell widths, steppers or outcomes.
- The greatest composition work is the relationship among preparation, warnings,
  execution and monitoring—not finding another primitive for each region.

## What this batch intentionally did not decide

- Exact current-section proportions, layout breakpoints, default-expanded detail
  regions, sticky actions or final heading hierarchy.
- Which existing messages need corrected wording, warning versus blocking
  semantics, transaction math, launch eligibility or hybrid/version policy.
- Removal of any production action, an assumed manual bidding form, a new chain,
  or simplification of repeated auctions into one transaction.
- Promotion of any provisional component or migration of any production caller.

These are not all designer decisions. Mechanics and source conflicts require
engineering disposition; missing wording requires approval. Pure composition
choices can be made after the functionality inventory is complete.
