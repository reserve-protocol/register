# Index DTF v6 — Register rebalance vertical (stages S2–S4 subset)

Execution contract for the first implementation effort under the [v6 integration plan](index-dtf-v6-integration.md). The [handoff](index-dtf-v6-handoff.md) owns the full 69-task breakdown; this document is the stage contract for the slices below and nothing else. Settled decisions in the integration plan are binding here.

Fixed point: Register `feat/index-dtf-v6` at `dba79019b` (cut from master `d0db7be93`). SDK `feat/index-dtf-v6-support` working tree (54 dirty files, built and green on 2026-09-16: 133 core + 85 React tests).

## Goal

Register's rebalance flow (list, detail, launch, community launch, basket proposal calldata) runs on the candidate `@reserve-protocol/react-sdk` 0.6.0 for Folio v5 and v6, keeps v4 on its Register-local path behind an explicit version switch, and is proven by unit differentials, the offline Playwright suite, and one real launch on the BSC fork. Each slice ends with a screenshot of the working surface.

## Current state

- Register reads live rebalance state through three raw wagmi multicalls (`use-rebalance-current-data.ts`, `use-rebalance-initial-data.ts`, `use-rebalance-params.ts`) selecting the v4 or v5 ABI from `getFolioVersion`, which maps every non-5 version to v4 (`utils/transforms.ts:19`). A v6 DTF would decode `getRebalance` with the v4 ABI and produce v4 calldata.
- `indexDTFVersionAtom` initializes to `'4.0.0'` and is never reset (`src/state/dtf/atoms.ts:141`, `reset-index-dtf-atoms.ts:47`), so every consumer sees a fabricated v4 during the load window.
- Both launch buttons call `writeContract` with the v5 ABI unconditionally and refresh with 10 s and 15 s timers instead of query invalidation (`launch-auctions-button.tsx:96-113`, `community-launch-auctions-button.tsx:71-88`).
- `basketProposalCalldatasAtom` picks `version.startsWith('5') ? 5 : 4` and encodes locally with `getStartRebalance` (`propose/basket/atoms.ts:513-599`). The submit button already uses SDK `prepareIndexDtfSubmitProposal`.
- Open-auction math is Register-local: `getRebalanceOpenAuction` wraps `dtf-rebalance-lib` `getOpenAuction` with product presets (percent default 98, volatility map, Ondo cap, chain floor).
- The SDK already exports `useIndexDtfCurrentRebalance` (accepts `blockNumber`), `useIndexDtfRebalances`, `useIndexDtfRebalanceAuctions`, `useIndexDtfLatestAuction`, `useIndexDtfActiveAuction`, pure `prepareIndexDtfOpenAuctionArgs` (v5 math only), `prepareIndexDtfOpenAuction` (v5 ABI, v6 ABI with `auctionLength`), `prepareIndexDtfOpenAuctionUnrestricted`, and `buildIndexDtfStartRebalanceArgs` (v5/v6). React SDK re-exports every pure core function.
- SDK defects confirmed against protocol source: `execution.ts:78` treats the bid window as `[start, end)` and ignores `rebalanceNonce`; Folio checks `startTime <= now <= endTime` and `auction.rebalanceNonce == rebalance.nonce` (`RebalancingLib.sol:457-465`). `start-rebalance.ts:29` defaults a missing version to `"5.0.0"`.
- Peer mismatch: React SDK 0.6.0 requires `@tanstack/react-query ^5.102.7`; Register resolves 5.99.0.
- Offline e2e covers the launch permission matrix on `bsc/cmc20` (`launch-write.spec.ts`) with mocked sends. The BSC fork stack is up at block 122310900 and answers CMC20 `version()` = `5.0.0`.

## Non-goals

- Bid, close and end product controls (none exist today; SDK runner coverage only).
- Upgrade flow (S5), native v6 deployment (S6), subgraph schema changes, Cowbot changes.
- Moving product policy (percent presets, volatility map, Ondo cap, chain floor, hybrid allowlist) into the SDK.
- Retiring the v4 Register-local encoder.
- Three-chain fork execution of the full cohort (S1). This effort proves one real launch on one chain.

## Slices

- Slice 1 — Version identity: `indexDTFVersionAtom` becomes `undefined` until `useIndexDtfVersion` resolves and resets on identity change; new derived `folioVersionAtom` (`pending | 4 | 5 | 6 | unsupported`); rebalance hooks and `basketProposalCalldatasAtom` consume it and fail closed. Screenshot: CMC20 rebalance detail unchanged. Blocked by: none.
- Slice 2 — Candidate SDK: active-auction window inclusive, nonce compared with `getRebalance().nonce`, and every read pinned to one resolved block; `version` required and runtime-validated (`5.0.0` | `6.0.0`, typed rejection otherwise) in `prepareIndexDtfOpenAuctionArgs`, `prepareIndexDtfOpenAuction`, `buildStartRebalanceArgs`, `buildIndexDtfStartRebalance` and the write-ABI selector; v6 open-auction math takes the same `auctionLength` the calldata uses; finite positive price validation before the library; link both SDK packages into Register; bump react-query to the SDK peer range and `dtf-rebalance-lib` to the SDK's range so one library instance resolves; Register gates green on the candidate. Blocked by: none (parallel with slice 1, same owner).
- Slice 3 — Reads via SDK: current/initial/historical rebalance reads, auctions history and rebalances list move to SDK hooks for v5/v6; v4 keeps the local wagmi reads; chain-aware keys. Ongoing-auction state for write gating derives from RPC (`useIndexDtfLatestAuction` with the fixed semantics), never from indexed auctions; indexed history reconciles against the receipt block. Screenshot: active detail on the offline fixture. Blocked by: 1, 2.
- Slice 4 — Calculations via SDK: `getRebalanceOpenAuction` delegates to `prepareIndexDtfOpenAuctionArgs` with `version`, keeping Register's price pre-check and volatility default in front; `basketProposalCalldatasAtom` delegates to `buildIndexDtfStartRebalanceArgs` (passing `deferWeights` as today) and SDK encoding for v5/v6; differential vectors cover native-snapshot, tracking and hybrid target-price modes plus a missing-volatility token; mutation test on the wiring seam. Screenshot: proposal preview calldata unchanged. Blocked by: 3.
- Slice 5 — Transactions via SDK: launch buttons submit `prepareIndexDtfOpenAuction` / `prepareIndexDtfOpenAuctionUnrestricted` calls through the existing transaction container; receipt clears the launching state and invalidates the RPC-backed SDK keys first, then reconciles indexed history once the subgraph reports the receipt block; v6 passes the RPC `maxAuctionLength` to both math and calldata; the community button gets its own version gate. Fork lane: per-chain RPC override for reads, Cowbot disabled by env, default-deny egress kept. Real launch on the BSC fork with screenshots. Blocked by: 4.
- Slice 6 — Closeout: full gate, whole-goal Intent and Engineering Risk reviews, wiki and area-guide ingest, PRs for Register and SDK. The SDK pair is not released: the Register PR pins a prerelease build (`next` dist-tag) or stays draft on a link until Luis publishes; production release remains behind the parent plan's full-suite gate. Blocked by: 5.
